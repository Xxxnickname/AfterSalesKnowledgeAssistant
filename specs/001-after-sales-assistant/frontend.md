# 前端规格（Frontend Spec）— 项目一

> 与 `04-界面与功能清单.md`「一、项目一」对应：8 屏。前端优先，先出可点版本，评审通过再做后端。

## 一、前端技术栈（冻结）

- **HTML + CSS + 原生 JavaScript (ES2020)**，无框架、无构建步骤，由 FastAPI `app/static/` 直接托管
- 样式：`tokens.css`（颜色/字号/间距/圆角/阴影）为唯一来源，禁止散落硬编码色值
- 状态：每个列表/详情页必须有 **加载中 / 空数据 / 无权限 / 错误** 四态
- 交互：按钮圆角矩形居中文字；危险操作二次确认；批量操作显示影响条数
- 数据：G1 阶段全部走 `static/mock/*.json`，用 `fetch` 读本地文件，接口地址集中在 `static/js/api.js` 一处，便于 G2 切换


**本地预览端口**：G1 阶段用 `python -m http.server 8001 --directory app/static` 预览，端口与后续后端一致；三项目可同时打开互不冲突。

## 二、8 屏清单与验收点

| 屏 | 路由（hash） | 关键元素 | 评审要点 |
|---|---|---|---|
| 1-1 客户聊天窗 | `#/chat` | 问候语、4 个快捷问题、输入框、图片按钮、转人工常驻 | 移动端 375px 不横向滚动；回答带「依据：手册 第 X 页」可展开 |
| 1-2 评价弹层 | `#/chat` 内弹层 | 1–5 星、可选文字 ≤200 | 提交后不可重复评价 |
| 1-3 坐席工作台 | `#/workbench` | 三栏：待接入列表 / 交接包+消息流 / 客户信息+推荐 Top3 | 接管按钮状态正确；交接包 4 段齐全可见 |
| 1-4 未命中问题池 | `#/unmatched` | 问题、次数、最近时间、样例会话、转 FAQ | 默认按次数倒序 |
| 1-5 知识库管理 | `#/kb` | 文档列表（型号/版本/解析进度）、FAQ Tab、术语 Tab | 解析进度可视化；下架有二次确认 |
| 1-6 数据看板 | `#/dashboard` | 4 张指标卡 + 2 张趋势图 + 差评列表 | 无数据时有空态，不是空白页 |
| 1-7 会话质检 | `#/qc` | 列表 + 详情（消息流/依据/操作记录）、标记问题类型 | 详情可跳回原会话 |
| 1-8 用户与角色 | `#/users` | 账号列表、新增/禁用/重置密码/分配角色 | 仅 admin 可见，越权显示 403 页 |

## 三、视觉与交互约束

- 字号阶梯：24/18/16/14/12；最多 3 种字体（系统中文 + 等宽数字）
- 颜色：主色 1 个 + 语义色 3 个（成功/警告/危险），全部走 `tokens.css` 变量
- 表格：斑马纹可选；超过 50 行分页；列可排序的要有箭头
- 时间统一 `YYYY-MM-DD HH:mm:ss`（Asia/Shanghai）
- 所有 403/404/500 使用同一套错误页模板，带 `trace_id` 与「重试」按钮
