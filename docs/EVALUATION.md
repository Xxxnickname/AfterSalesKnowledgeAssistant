# 评测说明

## 1. 数据口径

- 主评测集：`samples/01/eval_v1.jsonl`，120 条构造问题，覆盖 FAQ、口语化、多跳、故障诊断和表格查询。
- 构造压力集：在主评测集上做格式/口语变化，不冒充真实用户数据：
  - 型号去连字符：`NC-500` -> `NC500`
  - `怎么处理` -> `咋处理`
  - `保修期是多久` -> `保修多长时间`
  - `报警` -> `报错`
  - 去掉部分“的”和问号
- 数据中的客户、设备、工单和指标均为构造演示数据。

## 2. 指标定义

| 指标 | 定义 |
|---|---|
| Top-1 | 第一名候选的正文、章节或文档名能覆盖 expected_keywords |
| Top-3 | 前 3 名候选中有命中 |
| MRR | 首个命中候选排名的倒数均值 |
| 引用覆盖 | 返回答案包含至少一条可展示引用 |
| P95 | 请求时延的第 95 百分位 |

## 4. 端到端结果

- 120/120 通过，引用覆盖 100%。
- 本机响应时延 P50 / P95：0.03s / 0.05s。
- pytest：29 passed。
- DoD：18/18。
- 极端场景：19 PASS / 0 FAIL / 2 N/A。

N/A 项为磁盘写满和 200MB 文档上传端点，未构造，不写成 PASS。

## 6. 结果解释

- 120/120 是构造回归集的通过结果，不等于真实业务准确率。
- 压力集结果用于验证型号规范化和口语扩展的鲁棒性，不是线上用户数据。
- 业务提效（人工工时、首次解决率、转人工率）需要上线试点后测量；本仓库不使用 mock 看板数据冒充线上业绩。
